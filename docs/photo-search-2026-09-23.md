# 사진촬영 검색 설정

범위: /services/photo 소개·가격·업종 목록·32개 업체 상세, 총 36페이지.

## 변경

- 각 페이지의 canonical, Open Graph URL·설명·대표 이미지와 Twitter 카드를 일치시켰다. 목록 제목의 브랜드 중복을 제거했다.
- 상위 레이아웃의 서비스 및 breadcrumb 구조화 데이터를 소개 페이지로 옮겨 하위 페이지에서 중복 경로가 생성되지 않게 했다.
- 목록 CollectionPage·ItemList, 업체 상세 ImageGallery·ImageObject를 실제 카탈로그에서 생성한다. 미확인 저작권자·촬영자·리뷰를 추가하지 않는다.
- 340개 이미지 URL을 이미지 사이트맵에 연결했다. 수정일은 실제 이번 배포일로 고정했다.
- 가격 정본의 상품 6개를 OfferCatalog로 연결한다. 가격은 KRW, 부가세 별도이며 실제 페이지 앵커로 연결한다.
- 가격표에 비용·시간·보정 범위의 질문·답변 4개를 표시하고 같은 데이터로 FAQPage를 생성한다.
- llms.txt에 사진촬영 서비스, 가격, 32개 사례 링크를 정본에서 생성한다. 촬영 사례를 마케팅 성과와 구분한다.
- robots의 기존 공개 페이지 허용·비공개 경로 제한은 유지한다. AI 인용을 보장하는 잘못된 주석은 수정했다.
- 공용 JSON-LD 출력의 `<`를 이스케이프했다.

## 검증 기준

ESLint, TypeScript, 생산 빌드, 원고검사와 생성 HTML 검사. 36개 canonical·OG URL·Twitter 카드·breadcrumb 개수·제목 중복·본유 표기, 32개 갤러리의 이미지 수·원본 URL·PNG MIME, 6개 가격·부가세, 4개 화면 FAQ와 JSON-LD 일치, 이미지 사이트맵 340개와 llms 링크를 검사한다. 검수 중 PNG 1개의 MIME 오류를 수정했다.

로컬 빌드는 자원 절약을 위해 작업자 1개로 실행하고 설정 파일을 복구한다. 배포 설정은 바꾸지 않는다.

## 적용 기준과 한계

[Google AI 검색 안내](https://developers.google.com/search/docs/appearance/ai-features)에 따라 크롤링 가능한 본문·내부 링크·정확한 메타데이터와 구조화 데이터의 일치에 집중했다. llms.txt는 보조 자료이며 검색엔진의 채택이나 AI 인용을 보장하지 않는다. FAQ 구조화 데이터도 검색 특수 노출 보장을 뜻하지 않는다. 실제 색인·순위·AI 답변 채택은 배포 성공과 별개다.

[Next.js JSON-LD 가이드](https://nextjs.org/docs/app/guides/json-ld)의 안전한 직렬화 방식을 적용했다. 작업로그와 로컬 검사 스크립트는 공개 배포물에 넣지 않는다.


## 서비스 탐색과 반응형 개선

공개 서비스 정본 service-catalog.ts에서 마케팅 11종과 프로그램 1종을 홈·메뉴·푸터·구조화 데이터에 연결한다. 파워컨텐츠와 네이버 검색광고는 기존 가격표의 품목을 상세 카드로 보강한 것으로 새 단가를 만들지 않는다. 목적별 찾기는 방문자가 직접 누른 목적에 따라 목록과 순서를 변경하며 사용자 추적이나 AI 추론을 하지 않는다.

모바일 서비스 메뉴는 기본 접힘, 별도 펼침 버튼과 전체 서비스 링크를 제공한다. 모바일·PC 메뉴 모두 세로 공간을 넘으면 스크롤된다. 링크 선택·Escape 닫기, ARIA 상태, 44px 이상 주요 터치 영역을 반영했다. 모바일 자동 상담 팝업을 숨기고 기존 상담 진입점을 유지했다. 시스템 모션 감소 설정과 앵커 여백을 보완했다.

메인 FAQ 25개는 비용·계약5, 상담·진행·개업준비5, 검색·성과6, 채널6, 병의원3으로 분류한다. 주제와 답변은 기본 접힘이고 주제는 하나씩 열린다. 25개 질문·답변은 HTML에 모두 남으며 기존 FAQPage와 같은 내용이다.
